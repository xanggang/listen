# WorldTuner 电台数据采集与清洗流程

本文记录从 Radio Garden、Radio Browser 原始数据到 V2 SQLite 的完整处理链路。原始库只读保存，V2 库是整理后的业务数据；所有清洗写回都先生成独立备份，并在事务内校验。

## 1. 数据分层

```text
Radio Garden API
  └─ radio-garden/data/radio-garden.sqlite
       └─ radio-garden/processing/import-v2.mjs

Radio Browser API
  └─ radio-browser/data/radio-browser.sqlite
       └─ radio-browser/processing/import-v2.mjs

两类来源导入并合并
  └─ v2/data/worldtuner-v2.sqlite
       ├─ station / station_stream / station_link
       ├─ country / language
       ├─ tag / station_tag
       └─ station_source / moderation_record
```

原始数据库、V2 数据库和标签备份必须分开保存。任何处理脚本都不直接修改原始采集库。

## 1.1 数据来源与原始文件位置

### Radio Garden

Radio Garden 数据来自 Radio Garden 的地点、频道详情和播放重定向接口。网络请求由以下脚本完成：

- `radio-garden/src/fetch-places.mjs`：采集地点列表和地点坐标；
- `radio-garden/src/sync-api.mjs`：同步频道详情、页面响应和播放重定向；
- `radio-garden/src/api/client.mjs`：封装 HTTP 请求；
- `radio-garden/src/store.mjs`：把响应写入本地采集库。

原始数据保存于：

`worldTuner-data/radio-garden/data/radio-garden.sqlite`

该 SQLite 库保存 `api_responses`、`radio_garden_places`、频道与地点关系等采集结果。同步过程中的断点状态在 `radio-garden/data/sync-progress.json`，接口异常记录在 `radio-garden/log/api-errors.jsonl`。这些文件只用于继续采集和排查错误，不直接作为 V2 查询库。

常用采集命令（在 `worldTuner-data/` 下执行）：

```bash
npm run fetch:radio-garden
npm run sync:radio-garden:api
```

### Radio Browser

Radio Browser 数据来自 Radio Browser API。网络同步由以下脚本完成：

- `radio-browser/src/client.mjs`：封装 API 请求；
- `radio-browser/src/repository.mjs`：保存和查询原始记录；
- `radio-browser/src/sync.mjs`：执行完整同步。

原始数据保存于：

`worldTuner-data/radio-browser/data/radio-browser.sqlite`

该 SQLite 库保存 Radio Browser 返回的电台、播放地址、标签和统计字段。它是去重和字段合并的输入，不是最终 V2 数据库。

同步命令：

```bash
npm run sync:radio-browser
```

### V2 数据库位置

两个原始库经各自的 `processing/import-v2.mjs` 转换后，写入：

`worldTuner-data/v2/data/worldtuner-v2.sqlite`

V2 库只保存整理后的国家、电台、流、社交链接、来源、语言、标签及投诉记录。它不替代两个原始采集库；重新采集时先更新原始库，再按来源保护和增量策略更新 V2。

语言表中的 `code` 是 Radio Browser 的匹配键，统一保存为小写；`name` 是首字母大写的英文展示名，`name_zh` 是中文展示名。例如 `English / 英语 / en`。语言中文名由 `radio-browser/processing/language-names.zh-CN.json` 维护。

`radio_garden_country_names` 只表示 Radio Garden 国家英文名、中文名和国家代码的关系，不表示电台语言。Radio Garden 频道详情没有语言字段，因此不能从该表推断语言，也不建立国家到语言的一对一关系。语言关联只来自 Radio Browser 的 `languagecodes`，写入 `station_language`。

## 2. Radio Garden 数据处理

采集与同步脚本位于 `radio-garden/src/`，数据转换脚本位于 `radio-garden/processing/`。

`import-v2.mjs` 的处理顺序如下：

1. 从频道详情响应读取频道标题、`country.title`、`place.title`、`website` 和 `social`。
2. 通过 `place.id` 关联 `radio_garden_places`，取得纬度和经度。
3. 从 `stream_redirect` 响应取得 `redirect_url`，保存为流的 `resolved_url`。
4. `website` 原样写入 `station.website`。
5. `social[]` 每项拆成 `station_link.platform` 和 `station_link.url`；Radio Browser 的 homepage 使用 `platform = web`。
6. 依据国家名称映射国家代码，写入 `country` 和 `station.country_id`；无法确认代码时国家关系留空。
7. 生成 Radio Garden 来源记录和频道流记录。
8. 遇到缺失地点、无效频道详情或数据库约束错误时整批回滚。

Radio Garden 的 `page` 响应不作为电台导入；缺失地点和未采集详情会在导入结果中报告。

## 3. Radio Browser 数据处理

采集与同步脚本位于 `radio-browser/src/`，V2 转换脚本为 `radio-browser/processing/import-v2.mjs`。

### 3.1 电台去重

去重核心是实际播放地址：

1. 优先使用 `url_resolved`，缺失时使用 `url`。
2. 播放地址只清理首尾空白，不改变协议、大小写、查询参数和尾斜杠。
3. 相同播放地址视为同一电台。
4. 同组记录按可用状态、votes、clickcount、UUID 排序。
5. 字段合并遵循“有值优先”；冲突时 Radio Browser 字段优先。
6. 原始 UUID 和来源关系保存在 `station_source`，播放地址保存在 `station_stream`。

同一个电台可能有多个来源记录，但 V2 只保留一份 `station` 主记录。

### 3.2 电台字段整理

- `homepage` 写入 `station.website`。
- `state` 写入 `station.place`，只作为地点搜索文本，不维护行政区划层级。
- `votes`、`clickcount` 保留有效的非负整数。
- 经纬度必须成对且在合法范围内。
- `lastcheckok` 映射为 `catalog_status`。
- 无有效播放地址、名称或 UUID 的原始记录跳过并计数。

## 4. 标签清洗

标签清洗分为规则清洗和 AI 结果导入两层。

### 4.1 规则清洗

规则文件：

- `radio-browser/processing/tag-cleaning-rules.json`
- `radio-browser/processing/tag-names.zh-CN.json`

`report-tags.mjs` 只读分析标签，识别：

- 已知同义词和多语言别名；
- 音乐风格、节目类型和年代变体；
- 频率、码率、编解码格式、网址；
- 纯语种、纯符号、明确地名和传输信息；
- 含义不明确的品牌、人名和复合描述。

`clean-tags.mjs` 写回规则结果。写回前建立标签专用 SQLite 备份，使用事务重建 `tag` 和 `station_tag`，再检查标签集合、关联集合、外键和完整性。

### 4.2 AI 全量处理

AI 处理结果使用以下动作：

- `keep`：保留原标签；
- `merge`：合并到一个标准标签；
- `drop`：删除明确噪声；
- `split`：将明确的复合标签拆成多个目标。

`apply-ai-tags.mjs` 会校验：

1. 输入 ID 与数据库当前标签逐项一致；
2. 输出 ID 恰好覆盖全部输入且没有重复；
3. 原始名称没有被改写；
4. 目标数量符合动作要求；
5. 目标没有循环、删除冲突或中文冲突；
6. 一对多拆分后的 `station_tag` 关联没有重复；
7. 写回前备份，写回后逐条核对最终关联。

## 6. 备份和恢复

当前 `v2/data/` 只保留正式库 `worldtuner-v2.sqlite`；历史标签和全库快照已按项目清理要求删除。后续执行 `clean-tags.mjs --apply` 或 `apply-ai-tags.mjs --apply` 时仍会先自动生成备份，写入完成并确认不再需要后才可删除。恢复时必须使用当次操作生成的备份，不要手工拼接标签表。

## 7. 常用命令

在 `worldTuner-data/` 目录执行：

```bash
# 初始化空 V2 数据库；目标文件存在时会拒绝覆盖
npm run init:v2

# 导入两个来源；同一来源已有记录时会拒绝重复导入
npm run process:radio-garden:v2
npm run process:radio-browser:v2

# 只读生成标签规则报告
npm run report:radio-browser:tags

# 预览规则清洗；增加 --apply 才会写回
npm run clean:radio-browser:tags
npm run clean:radio-browser:tags -- --apply

# 预览或写回已校验的 AI 全量结果
npm run apply:radio-browser:ai-tags
npm run apply:radio-browser:ai-tags -- --apply

# 运行相关测试
npm run test:radio-browser
```

完整导入不是增量同步。由于来源保护机制已经存在，重复执行会被拒绝；后续需要新增数据时应实现增量同步流程，不能删除来源记录后强行重跑。
