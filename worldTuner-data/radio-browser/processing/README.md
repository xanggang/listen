# Radio Browser → V2 数据处理

在 `worldTuner-data/` 目录执行：

```bash
npm run process:radio-browser:v2
# 可选：--source 原始库路径 --target V2 库路径 --worker-id 0-1023
```

默认只读 `radio-browser/data/radio-browser.sqlite`，写入 `v2/data/worldtuner-v2.sqlite`。源库不会修改；已存在 Radio Browser 来源记录时拒绝再次导入。整批写入在事务中完成，出错回滚。

按 `url_resolved`（缺失时用 `url`）的完整地址精确去重。相同地址的 Radio Browser 记录与已有 Radio Garden 电台合并；所有来源 ID 保留在 `station_source`。非空字段优先取 Radio Browser，空值保留 Radio Garden 字段。同来源记录按最后检查、票数、点击数和 UUID 稳定排序后逐字段补空值。无地址或同组无名称的记录跳过并计数。详见 [设计文档](../../v2/docs/电台数据库设计.md)。

## 标签清洗建议报告

运行 `npm run report:radio-browser:tags`，只读分析 V2 的 `tag` 和 `station_tag`，默认输出到 `v2/docs/标签清洗报告/`。可通过 `--db`、`--output` 指定输入和报告目录。

`tag-cleaning-rules.json` 是导入与清洗共用的规则词典。报告列出高频标签、别名合并候选、忽略候选、异常文本，并在完整 JSON 中保存每个标签的 ID、关联数量、建议原因及电台样例。报告命令仅用于生成建议与模拟统计，不修改数据库；清洗命令的 `--apply` 才写回。未知和低频标签保留，待审表示尚无可靠规则，不要求逐项手动操作。

`tag-names.zh-CN.json` 保存标准英文键对应的中文展示名称。生成报告时同时输出 `标准标签中英对照.md` 和 `标准标签中英对照.json`，覆盖当前保留及合并候选的标准标签；待审标签暂不翻译。电台数量是合并别名后去重的模拟结果。

清洗脚本执行 `--apply` 时会为旧库增加 `tag.name_zh` 并写入已知中文名；新建库和新导入的标签也使用该列。未知项保留已有中文或 `NULL`，旧版三列备份仍可恢复，新备份包含中文。当前默认 V2 库中 1,358 个标签已有中文，标签总数为 8,656（含 AI 结果入库）。请连接 `v2/data/worldtuner-v2.sqlite`；`v2/worldtuner-v2.sqlite` 是另一份空库。

## 标签备份、清洗和恢复

```bash
# 预览当前库的清洗结果
npm run clean:radio-browser:tags
# 先备份 tag 和 station_tag，再原子写回清洗结果
npm run clean:radio-browser:tags -- --apply
# 从指定标签专用快照恢复；恢复前也会备份当前标签
npm run clean:radio-browser:tags -- --restore 标签备份.sqlite
```

可选 `--db V2库路径` 和 `--backup 新备份路径`。默认快照与 V2 库放在同一目录，名称带时间，已有文件不覆盖。快照包含原标签、全部关联、规则和每个旧标签的去向。只处理明确忽略项、已列出的别名以及 NFKC/空白/大小写重复；待审标签继续保留，不自动限制到标准词表。既有标准标签 ID 优先沿用，合并后的关系去重。完整性、外键及逐条关系核对失败会整体回滚。

2026-09-30 首轮清洗已执行：12,356 → 11,982 个标签，152,264 → 136,430 条关联；忽略 332 个标签，归并 42 个重复标签。11,893 个非标准标签仍保留待审。详细结果与备份路径见 `v2/docs/标签清洗报告/清洗执行结果.json`；逐项去向见 `清洗去向.json`。原始 Radio Browser 库未改动；新建 V2 库时，Radio Browser 导入脚本已复用同一清洗规则。

## AI 全量结果入库（2026-09-30）

`apply-ai-tags.mjs` 校验原始输入、AI 结果和当前库的一致性，支持 keep/merge/drop/split 及连续目标映射。默认只读预览，`npm run apply:radio-browser:ai-tags -- --apply` 先备份再原子写回。路径可用 `--db`、`--input`、`--results` 指定。它保留既有标准 ID，合并重用旧 ID，拆分确实需要新增 ID 时生成 19 位雪花字符串。发现漏项、重复 ID、原名过期、目标数量不合规、循环或中文冲突时拒绝写入。

本轮已处理全部 10,803 条 AI 输出：drop 1,669、merge 783、split 94、keep 8,257。最终 tag 8,656、station_tag 107,768、name_zh 非空 1,358；7,298 个未确定中文的标签继续保留。原有 419 个标准标签逐行未变。

记录位于 `v2/docs/标签清洗报告/AI处理包/入库结果.json`、`入库关联映射.json`、`入库校验.json` 和 `入库后全部标签.json`。所有最终关联独立按备份的一对多映射核对一致；其他表行数不变，外键和完整性检查通过。相关 10 项测试通过。

输入和 AI 结果是本次原始快照；入库后再次执行会因当前库已变化而拒绝，不能将历史结果当作增量同步规则。需要恢复时可使用 `clean-tags.mjs --restore <入库结果中记录的备份路径>`；恢复也会备份当前标签状态。单目标规则脚本与原始 AI 结果保留用于追溯，当前库最终状态以 `入库后全部标签.json` 为准。
