# 管理端开发与部署

## 项目边界

前端：`worldTuner-admin`，独立依赖、构建、测试。后端：`worldTuner-admin-api/src`，独立业务模块；入口 `src/index.ts`，配置 `wrangler.jsonc`。两者作为一个 `worldtuner-admin` Worker 部署，同属主仓库，但依赖、源码、构建、测试与配置独立。客户端仍是 `worldtuner-api` Worker，不能访问 `/admin/api`。

数据库仍为业务 DB + 运营 METRICS_DB。业务 schema 由 data 项目负责，新增 `v2/migrations/0002_admin_outbox.sql`；运营新增 `worldTuner-data/operations/migrations/0002_admin.sql`。普通客户端只写受控统计入口，不写管理表。

## 管理接口

全部路径前缀 `/admin/api`，GET 允许 owner/viewer，PUT 仅 owner；写入需要同源 Origin 与 `X-CSRF-Token`。

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | `/me` | 当前管理员、角色、短期 CSRF、缓存说明 |
| GET | `/health` | 已认证服务探活 |
| GET | `/stations` | 全部电台分页，含下架/失效；q、countryId、languageId、tagId、visibility、status |
| GET | `/stations/{id}` | 管理详情与全部播放流 |
| PUT | `/stations/{id}` | 基本字段与目录状态；expectedUpdatedAt 乐观锁 |
| PUT | `/stations/{id}/visibility` | 软上下架，expectedUpdatedAt |
| PUT | `/stations/{id}/streams/{streamId}` | 编辑已有播放流，校验所属电台与版本 |
| GET | `/catalog/{kind}` | countries/languages/tags 全量分页搜索 |
| PUT | `/catalog/{kind}/{id}` | 中英文校订，旧译名快照检查并发冲突 |
| GET | `/analytics` | UTC 日 PV/UV 与月 MAU，from/to/source，最多 31 天 |
| GET | `/analytics/overview` | 同口径统计与电台目录状态分布 |
| GET | `/reports` | 错误摘要、处理状态筛选与分页；目前未接入客户端上报 |
| PUT | `/reports/{id}/status` | 报告状态处理，expectedStatus 乐观锁 |
| GET | `/audit` | 管理操作审计分页，只读 |
| GET | `/logs` | 固定 Cloudflare 控制台入口及能力说明 |

默认分页 20、最大 50、最多 1000 页；搜索最多 100 字，JSON 最大 16 KB。详情不返回 station 内部主键。SQL 值绑定、表名固定映射、写字段白名单、错误响应隐藏 SQL/堆栈。机器契约见 `worldTuner-admin-api/docs/openapi.json`。

## 本地环境

启动方式见 [管理前端 README](../worldTuner-admin/README.md)。`dev:sqlite` 使用本机 Node、SQLite，单独 `.env.sqlite`。local 模式仅允许 loopback URL，自动连接已启用的 local-owner，无需配置或输入登录密钥。CSRF 签名密钥由本地进程自动生成，写入仍校验角色、同源及 CSRF；生产仍要求 Access 与独立配置的 CSRF_SECRET。

本地服务创建的 `local-owner` 只用于隔离开发。生产无本地 Token 回退，旧 ADMIN_TOKEN 也无效。生产管理员不自动按邮箱或首次登录创建。

## 生产部署准备

1. 在 Cloudflare Access 中创建覆盖整个管理域名的应用，限制明确身份并要求 MFA。将真实管理域名配置到管理 Worker 的路由，不使用文档中的 example.com。`workers_dev`、预览地址默认关闭。
2. 填写 `ADMIN_ORIGIN`（不带末尾斜线的 HTTPS origin）、`ACCESS_ISSUER`（如 `https://你的团队.cloudflareaccess.com`）、`ACCESS_AUDIENCE`。运营 D1 的全零 ID 必须替换，且两 Worker 的业务/运营绑定必须分别指向同两个真实数据库。
3. 设置管理 Worker Secret：`pnpm exec wrangler secret put CSRF_SECRET --config wrangler.jsonc`，至少 32 字符，使用随机值，不提交到 Git。
4. 确认备份、迁移记录及数据库目标后分别执行 DB 和 METRICS_DB 的迁移。业务库增量增加 outbox，运营库新增管理员/审计/报告表；不重建电台表，不自动删除历史数据。

```sh
# 在 worldTuner-admin-api 目录；正式写库操作应在发布窗口执行。
pnpm exec wrangler d1 migrations apply DB --remote --config wrangler.jsonc
pnpm exec wrangler d1 migrations apply METRICS_DB --remote --config wrangler.jsonc
```

5. 用明确的 issuer + Access subject 通过受控 SQL 初始化管理员：先确认身份提供商的真实 subject，再写入 `admin_actors`。不只按邮箱授权，不提供公开注册或“首位访客变管理员”。

```sql
-- 将占位内容替换为可信身份信息，再通过受控发布文件执行。
INSERT INTO admin_actors(id,issuer,subject,email,role,enabled)
VALUES ('你生成的UUID','https://你的团队.cloudflareaccess.com','可信Access-subject','管理员邮箱','owner',1);
```

viewer 仅可读；停用将 enabled 改为 0，每个请求都会重新检查，已存在 JWT 也不能绕过。记录管理员变更 SQL 的发布审查；本版不提供网页新增或修改管理员的接口。

6. 构建前端，再 dry-run 管理 Worker，在独立预发布 D1 与域名验证 JWT、MFA、CSRF、viewer、隐藏数据、并发编辑、审计恢复和缓存，再部署。Cloudflare Account ID 可选，仅用于生成固定的日志控制台链接。

Access JWT 用 jose 限定 RS256 并验证签名、issuer、audience、exp、iat 与 subject；JWKS 只取服务器配置的团队证书 URL，支持缓存与密钥轮换。MFA 在 Access 策略中要求，应用不伪称已代替身份供应商执行 MFA。

## 审计与缓存

业务修改和 outbox 同库事务提交。修改使用最新 updated_at 或原译名快照作乐观锁，冲突 409 要求重新读取。播放流检查归属，不能通过另一电台 ID 修改。报告状态与审计都在运营库，使用同库事务。

每次成功写请求尝试投递最多 100 条 outbox 到运营库，以事件 ID 幂等去重；失败后事件仍保留。管理 Worker 每 10 分钟补投，SQLite 每分钟补投。确认已交付超过 7 天的 outbox 才分批清理，不清理未交付事件。审计不保存完整 URL、请求体、Token，只保存身份、动作、实体、变更字段名、时间与 requestId。

公开列表/详情/字典服务端缓存改为 60 秒，并更换内部版本避开旧缓存；地图按配置 TTL（默认 300 秒）。这不是全局即时失效；App 已加载的内存列表、收藏信息可能要重新进入或重启才能刷新。管理数据和静态页面均 no-store；浏览器不缓存带身份响应。

## 两个 API 已拆为独立项目

当前目录为 worldTuner-api（客户端后端）、worldTuner-admin-api（管理后端）、worldTuner-admin（管理前端），三者并列。管理后端路由已从 src/admin 下迁到独立项目的 src/stations、catalog、analytics、reports、audit，src/app.ts 统一装配；旧客户端管理路由已删除。管理后端的源码、测试和构建不导入客户端后端文件。端口与 /admin/api 契约不变。

两库迁移都由 data 项目集中维护；移动 SQL 不改迁移文件名或数据库记录。两个本地 SQLite 服务通过配置同一 METRICS_SQLITE_PATH 共享统计，示例地址保留原客户端的统计文件，未自动搬动任何数据库。Wrangler 本地 D1 默认按项目保存状态，不会因为远程 ID 相同而自动共享；需要联调时，迁移和两个 dev 命令都要显式使用相同的 `--persist-to` 目录。SQLite 联调不需要这个参数。

拆分后从 worldTuner-admin-api 运行 pnpm dev:sqlite / pnpm test / pnpm build / pnpm deploy；生产密钥与数据库迁移命令也在该目录运行。不再从客户端目录使用 dev:admin 等命令。

拆分后已重新运行两个 API 的独立构建与测试，并使用临时 Workerd/D1 及 SQLite + Vite HTTP 验证迁移后的鉴权、保存、审计交付和前端代理。没有修改原统计/业务数据库，也没有远程部署。
