# 客户端迭代与部署

本轮只处理客户端 API、Web 和 Android。管理前端、管理 Worker、管理员登录、日志查询和新增错误上报暂缓。

## 当前结构

| 部分 | 当前入口与配置 |
| --- | --- |
| 客户端 Worker | `worldTuner-api/src/index.ts` → `src/apps/client-app.ts`；`wrangler.jsonc` |
| 本地 SQLite API | `worldTuner-api/runtime/server.ts`，使用同一个客户端应用 |
| 业务 D1 | 保留 `DB` 绑定名称，迁移目录 `../worldTuner-data/v2/migrations/` |
| 独立统计 D1 | `METRICS_DB`，迁移目录 `migrations/operations/` |
| Web | 保留 Next.js/OpenNext，生产通过 `LISTEN_API` 绑定调用 `worldtuner-api` |
| Android | 构建时注入 `API_BASE_URL`、`MAPTILER_API_KEY` |

`/api` 路径、7 位电台 public_id、分类 ID、中英文、搜索、榜单和地图快照保持现有契约。Web/Android 无须因为后端分库而更改请求格式。

默认 Worker/SQLite 入口不加载管理业务模块，`/admin/api` 的 GET/PUT 返回 404，即使设置旧 `ADMIN_TOKEN` 也不会启用。历史组合应用 `src/app.ts` 仅保留供旧契约测试，不部署，也不是已完成的新管理端。

业务库只用于电台查询，PV/UV 只写独立统计库。缺少统计绑定时，上报返回 `503 METRICS_UNAVAILABLE`，电台读取继续可用；配置成同一个连接也会拒绝。D1 两个绑定必须填写不同数据库 ID，不能依赖代码对不同对象的底层库身份进行识别。每日汇总 Cron 暂由客户端 Worker 执行。

## 本地启动：优先 SQLite

使用电脑已安装的 pnpm，不安装项目内 pnpm 或创建项目内 store。

```sh
cd /Users/lin/Documents/www/lin/worldtuner/worldTuner-api
command -v pnpm
# 仅首次创建；已有 .env.sqlite 时编辑它，不覆盖本机配置。
test -f .env.sqlite || cp .env.sqlite.example .env.sqlite
pnpm dev:sqlite
```

默认只读业务库：`worldTuner-data/v2/data/worldtuner-v2-public.sqlite`；独立统计库：`worldTuner-api/.local/metrics.sqlite`。业务库必须有 public_id 和国家/标签/语言译名字段；启动时校验，不自动修改业务库。

Web 在另一个终端运行：

```sh
cd /Users/lin/Documents/www/lin/worldtuner/worldTuner-web
pnpm dev
```

开发默认调用 `http://127.0.0.1:8787`。需要覆盖时配置服务端 `LISTEN_API_BASE_URL`，根地址不包含 `/api`。

Android 模拟器：

```sh
cd /Users/lin/Documents/www/lin/worldtuner/worldTuner-mobile
flutter devices
flutter run -d <实际设备ID> --dart-define-from-file=env/local.json
```

本机 `env/local.json` 的 API 地址应为 `http://10.0.2.2:8787`，并填写地图 Key。真实手机改用电脑局域网地址，API 监听 `0.0.0.0`。不替你安装或启动真机应用。

## 本地 D1（可选）

从 `worldTuner-api` 运行，以下均只操作本地 D1：

```sh
pnpm db:migrate:local
pnpm db:export:catalog ../worldTuner-data/v2/data/worldtuner-v2-public.sqlite /tmp/worldtuner-catalog.sql
pnpm exec wrangler d1 execute DB --local --file /tmp/worldtuner-catalog.sql
pnpm dev --ip 0.0.0.0
```

导出目标文件必须不存在，数据只导入一次且目标业务表必须为空。业务数据不导入 `METRICS_DB`。完整数据量较大，日常调试用 SQLite 即可。

## Cloudflare 发布准备

本轮没有创建云资源、远程迁移或部署。`wrangler.jsonc` 保留业务库 `tuner` 的现有 ID；统计库 ID 暂为全零占位值，不能直接发布。

1. 创建独立运营 D1，例如 `pnpm exec wrangler d1 create worldtuner-operations`，将返回 ID 填到 `METRICS_DB`。填写真实 Web Origin 到 `ALLOWED_ORIGINS`。
2. 先确认业务库实际数据、备份和 `d1_migrations` 记录，再运行业务迁移；已有数据不要再次导入全量 INSERT。
3. 分别迁移业务和统计库：

```sh
pnpm exec wrangler d1 migrations apply DB --remote
pnpm exec wrangler d1 migrations apply METRICS_DB --remote
```

4. 仅空业务库执行一次导入：`pnpm exec wrangler d1 execute DB --remote --file /tmp/worldtuner-catalog.sql`。已有库需要先离线确认 public_id 回填完整，初始化 SQL 不会自动生成它。
5. 验证数据与 public_id、中英文后执行 `pnpm deploy`；确认公开 HTTPS `/api/health`、列表、详情和地图均正常，再发布 Web 和构建 Android 包。

Web 的 `LISTEN_API` 已指向 `worldtuner-api`，名称保持不变。Android 用实际 Worker HTTPS 根地址注入 `API_BASE_URL`，不包含 `/api/health`，不在安装包中放服务端 Secret。暂不恢复之前移除的线上地址。

已确认远程为空库，因此业务历史迁移合并为 `worldTuner-data/v2/schema.sql`，统计库为 `operations/0001_operations.sql`，每库独立编号。业务基线直接引用 `worldTuner-data/v2/schema.sql`，直接创建中英文列与 public_id 及索引。译名与 public_id 在本地数据处理时补齐，再随导出数据导入；空库建表不包含无效的译名 UPDATE。未来已有部署后新增变更，再各自添加增量迁移，不改已执行基线。

这次只整理 SQL，没有删除或重建任何本地数据库。若本机旧的本地 D1 已应用之前的拆分迁移，它的迁移记录不适用于新基线；请使用新的本地持久化目录初始化与导入（Wrangler 命令统一加 `--persist-to /tmp/worldtuner-d1-baseline`），保留旧目录供回退。SQLite 现有业务数据不受影响。

如果旧业务库已有统计表，切换不会删除它们，也不会自动复制历史统计。需要保留历史 PV/UV 时，先停止旧统计写入，备份并将五张 `metric_*` 表复制到空运营库，核对行数和汇总，再切换 Worker；避免双写及重复导入。未完成复制前，新运营库只统计切换后的数据。回退时恢复原 Worker 版本和配置，已产生的新统计需另行核对，不自动跨库合并。

## 验收范围

验证 API 的电台、分类、筛选、详情/播放地址、地图 gzip/ETag、限流、统计事务与两库边界；Web 接口契约、类型和 lint；Flutter 单元/页面测试和静态分析。真实手机播放、地图瓦片、线上 D1 耗时及发布后的全链路效果仍需实际环境验收，不能用本地测试代替。


2026-10-16 本地验证结果：API 25 项测试、类型/格式检查和 Worker dry-run 构建通过；Web 11 项测试和类型检查通过，lint 只有原有的 3 条 img 提示；Flutter 29 项测试与 analyze 通过。通过默认客户端入口只读访问真实 public SQLite 库，健康、列表、国家、语言、标签、中文搜索、详情和全量地图均返回 200，地图包含 42,704 个可展示点位。未进行真机、截图、远程 D1 或线上发布验证。

业务结构只维护 `worldTuner-data/v2/schema.sql`。`worldTuner-data/v2/migrations/0001_catalog.sql` 是指向它的相对符号链接，让 Wrangler 保持编号迁移记录；API 的初始化命令不变。发布或复制代码时保留 data/API 相邻目录和符号链接。
